# 权限配置说明

本文档说明 `config/knowledge_permissions.json` 的结构、当前权限映射和扩展方式。

## 1. 权限模型

项目使用模拟权限等级，不做完整用户登录。

等级关系：

```text
L1 < L2 < L3 < L4 < L5
```

继承规则：

- L1 只能访问 L1。
- L2 可以访问 L1-L2。
- L3 可以访问 L1-L3。
- L4 可以访问 L1-L4。
- L5 可以访问全部已配置知识库。

默认策略：

```json
{
  "default_access": "deny"
}
```

未配置的文档默认不允许访问。

## 3. 配置文件结构

配置路径：

```text
config/knowledge_permissions.json
```

单个知识库配置示例：

```json
{
  "knowledge_base": "HR 基础制度库",
  "required_level": "L2",
  "permission_code": "KB.HR.BASIC.READ",
  "document_names": [
    "HR基础制度库",
    "HR基础制度库.pdf",
    "HR基础制度库_正式版",
    "HR基础制度库_正式版.pdf"
  ],
  "document_patterns": [
    "*HR基础制度库*"
  ]
}
```

字段说明：

- `knowledge_base`：知识库展示名。
- `required_level`：访问该知识库所需最低等级。
- `permission_code`：权限码，便于后续接入真实权限系统。
- `document_names`：精确匹配文档名，检索前过滤主要依赖它。
- `document_patterns`：通配符兜底匹配，检索后过滤会使用。

## 4. Pipeline 中的权限校验位置

完整 RAG 中有两层权限控制：

```text
stage_apply_permission
-> stage_retrieve
-> stage_filter_retrieval_permission
```

第一层：检索前过滤

- 根据 `permission_level` 找到可访问知识库。
- 把可访问文档写入 `retrieval_inputs.document_names`。
- 如果用户显式指定了无权限文档，会提前结束。

第二层：检索后兜底过滤

- 读取每个 hit 的 `metadata.document_name`。
- 再次判断是否有权限。
- 删除无权限的 hits 和 expanded_context。

## 5. 检查权限配置

查看 L3 可访问内容：

```powershell
.\.venv\Scripts\python.exe nodes\auth\PermissionGuard.py --permission-level L3
```

指定配置文件：

```powershell
.\.venv\Scripts\python.exe nodes\auth\PermissionGuard.py `
  --permission-level L4 `
  --config config\knowledge_permissions.json
```

## 6. 新增知识库

新增 PDF 后，建议按以下步骤处理：

1. 把 PDF 放入 `data/`。
2. 在 `config/knowledge_permissions.json` 增加 `knowledge_bases` 条目。
3. 在 `document_names` 中写入不带 `.pdf` 和带 `.pdf` 的真实文件名。
4. 在 `document_patterns` 中写入可兜底匹配的通配符。
5. 运行 `rags/IngestPipeline.py` 入库。
6. 用对应权限等级运行 RAG 验证。

示例：

```json
{
  "knowledge_base": "新知识库",
  "required_level": "L3",
  "permission_code": "KB.NEW.READ",
  "document_names": [
    "新知识库",
    "新知识库.pdf",
    "新知识库_正式版",
    "新知识库_正式版.pdf"
  ],
  "document_patterns": [
    "*新知识库*"
  ]
}
```

## 7. 注意事项

- 权限过滤依赖 Chroma metadata 中的 `document_name`。
- 真实 PDF 改名后，建议同步更新 `document_names`。
- `document_patterns` 不能替代检索前精确过滤；它主要用于检索后兜底。
- 如果后续接入真实用户系统，可以把当前 `permission_code` 映射到用户拥有的权限码集合。
- 外部模型重排必须放在权限过滤之后，避免无权限内容发送给模型服务。
