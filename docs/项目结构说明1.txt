核心处理链路：

1. 文档解析：data/*.pdf -> MinerUStandardReader.py -> MinerUResult/<文档名>_<hash>/full.md
2. 数据清洗：full.md -> DataClean.py -> DataCleaned.md
3. 文档分片：DataCleaned.md -> HybridMarkdownChunk.py -> DataCleaned.hybrid_chunks.json
4. 向量入库：DataCleaned.hybrid_chunks.json -> ChromaBailianEmbedding.py -> Chroma 向量库
5. 问题前处理：IntentRouter.py / QuestionRewriter.py / PseudoAnswer.py
6. 权限控制：PermissionGuard.py 根据 config/knowledge_permissions.json 限制可检索知识库
7. 检索召回：ChromaRetriever.py 从 Chroma 中召回候选 chunk
8. 二阶段重排：Reranker.py 对权限过滤后的检索结果做规则重排和 MMR
9. 上下文压缩：ContextCompressor.py 压缩检索结果并生成 citations
10. Prompt 组装：PromptBuilder.py 生成最终 messages
11. RAG 编排：RAGPipeline.py 支持单次问答和循环问答

注意事项：

1. `__pycache__` 是 Python 运行生成的缓存目录，不属于业务结构说明重点。
2. `retrieval_result.json`、`compressed_context.json`、`final_prompt.json` 是调试输出文件，可按需重新生成。
3. 不建议使用 PowerShell 的 `>` 保存 JSON，可能写成 UTF-16；优先使用脚本自带 `--output`。
4. 权限配置依赖 Chroma metadata 中的 `document_name`，新增 PDF 后建议同步维护 `config/knowledge_permissions.json`。
5. `README.md` 是项目入口文档；更细的节点和策略说明放在 `docs/`。
6. 入库、运行、权限、日志分别有独立说明文档，优先查看对应主题文档。
