# 知识库入库流程

本文档说明 PDF 从上传到向量库的完整构建流程。推荐优先使用 `rags/IngestPipeline.py`，分步节点主要用于调试。

## 1. 输入目录

把 PDF 放在项目根目录：

```text
data/
```

当前权限配置已覆盖以下正式版文档：

```text
公司公开制度库_正式版.pdf
HR基础制度库_正式版.pdf
HR薪酬制度库_正式版.pdf
销售产品资料库_正式版.pdf
销售价格策略库_正式版.pdf
法务合同模板库_正式版.pdf
财务预算知识库_正式版.pdf
```

新增 PDF 后，需要同步检查 `config/knowledge_permissions.json`，确保文档名可以被权限配置匹配。

## 2. 一键入库

预览待处理 PDF：

```powershell
.\.venv\Scripts\python.exe rags\IngestPipeline.py --dry-run
```

执行完整入库：

```powershell
.\.venv\Scripts\python.exe rags\IngestPipeline.py
```

输出执行摘要到 JSON 文件：

```powershell
.\.venv\Scripts\python.exe rags\IngestPipeline.py --output ingest_result.json
```

## 3. 处理链路

```text
data/*.pdf
-> MinerUStandardReader.py
-> MinerUResult/<文档名>_<hash>/full.md
-> DataClean.py
-> DataCleaned.md
-> HybridMarkdownChunk.py
-> DataCleaned.hybrid_chunks.json
-> ChromaBailianEmbedding.py
-> ChromaDB
```

## 4. 增量规则

MinerU 解析：

- 使用文件内容 hash + 解析参数做缓存身份。
- 相同 PDF 内容默认不重复上传 MinerU。
- 文件改名但内容不变时，会尽量复用已有解析结果。
- 使用 `--force-reparse` 可以强制重新上传解析。

清洗和分片：

- 默认根据 `MinerUResult` 重新生成 `DataCleaned.md` 和 `DataCleaned.hybrid_chunks.json`。
- 如果只想复用已有 MinerU 结果，可使用 `--skip-mineru`。

Embedding：

- 默认读取 `DataCleaned.hybrid_chunks.json`。
- 只处理 `should_embed=True` 的 chunk。
- `CHROMA_SYNC_MODE=chunk` 时按 chunk 级别增量同步。
- 已存在且未变化的 chunk 会跳过。
- 新增或内容变化的 chunk 会写入新向量。
- 同一 document_id 下已经不存在的旧 chunk 会从 Chroma 删除。

## 5. 常用参数

跳过 MinerU：

```powershell
.\.venv\Scripts\python.exe rags\IngestPipeline.py --skip-mineru
```

强制重新解析：

```powershell
.\.venv\Scripts\python.exe rags\IngestPipeline.py --force-reparse
```

跳过清洗：

```powershell
.\.venv\Scripts\python.exe rags\IngestPipeline.py --skip-clean
```

跳过分片：

```powershell
.\.venv\Scripts\python.exe rags\IngestPipeline.py --skip-chunk
```

只解析、清洗、分片，不入向量库：

```powershell
.\.venv\Scripts\python.exe rags\IngestPipeline.py --skip-embedding
```

指定目录：

```powershell
.\.venv\Scripts\python.exe rags\IngestPipeline.py `
  --data-dir data `
  --result-dir MinerUResult
```

## 6. 分步执行

```powershell
.\.venv\Scripts\python.exe nodes\documents\MinerUStandardReader.py
.\.venv\Scripts\python.exe nodes\documents\DataClean.py
.\.venv\Scripts\python.exe nodes\chunks\HybridMarkdownChunk.py
.\.venv\Scripts\python.exe nodes\embeddings\ChromaBailianEmbedding.py
```

分步执行适合定位某一阶段的问题；正常构建建议使用一键入库脚本，避免漏跑节点。

## 7. 删除文档后的处理

删除 `data/` 里的 PDF 不会自动删除 Chroma 中的历史向量。

如果彻底删除某个 PDF，建议同时删除对应 `MinerUResult/<文档名>_<hash>/`，再执行：

```powershell
.\.venv\Scripts\python.exe nodes\embeddings\ChromaDocumentCleaner.py --prune-missing
```

更详细说明见：

```text
docs/删除向量库数据.txt
```

## 8. 常见问题

入库很慢：

- MinerU 是外部解析服务，首次解析 PDF 会慢。
- Embedding 需要调用百炼接口，chunk 数越多越慢。
- 再次运行时应优先命中 MinerU 缓存和 chunk 增量。

权限无法命中文档：

- 检查 Chroma metadata 中的 `document_name`。
- 检查 `config/knowledge_permissions.json` 的 `document_names` 是否包含真实文档名。

JSON 文件读不出来：

- 不建议用 PowerShell 的 `>` 保存脚本输出。
- 优先使用脚本自带 `--output` 参数，避免 UTF-16 编码问题。
