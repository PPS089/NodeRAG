# 日志说明

本文档说明 RAG Pipeline 的结构化日志格式、目录规则和排查方法。

## 1. 日志位置

默认日志根目录：

```text
logs/
```

默认文件结构：

```text
logs/YYYY/MM/YYYY-MM-DD.jsonl
```

示例：

```text
logs/2026/05/2026-05-28.jsonl
```

日志目录由 `utils/RAGLogger.py` 自动创建，默认不提交版本库。

## 2. 时区规则

日志使用上海时区：

```text
Asia/Shanghai
```

每条日志包含：

```json
{
  "ts": "2026-05-28T13:03:10.240129+08:00",
  "timezone": "Asia/Shanghai"
}
```

## 3. 事件类型

当前主要事件：

```text
pipeline_start
pipeline_end
pipeline_error
stage_start
stage_end
stage_error
```

每行是一条 JSON，便于后续接入日志采集或监控系统。

## 4. 常见字段

```text
ts              # 上海时区时间
timezone        # Asia/Shanghai
trace_id        # 单次请求链路 ID
event           # 事件类型
stage           # 当前阶段
status          # success/error/skipped
elapsed_ms      # 阶段耗时
metrics         # 阶段指标
error_type      # 异常类型
error_message   # 异常信息
```

`metrics` 中常见字段：

```text
pipeline_mode
hit_count
filtered_hit_count
context_block_count
citation_count
permission_level
```

## 5. 启用和关闭

默认启用日志：

```powershell
.\.venv\Scripts\python.exe rags\RAGPipeline.py --question "测试问题"
```

关闭日志：

```powershell
.\.venv\Scripts\python.exe rags\RAGPipeline.py --no-log --question "测试问题"
```

指定日志根目录：

```powershell
.\.venv\Scripts\python.exe rags\RAGPipeline.py `
  --log-file logs `
  --question "测试问题"
```

指定具体 JSONL 文件：

```powershell
.\.venv\Scripts\python.exe rags\RAGPipeline.py `
  --log-file logs\debug.jsonl `
  --question "测试问题"
```

如果 `--log-file` 是目录，日志按年月日分文件；如果是 `.jsonl` 文件，则写入指定文件。

## 6. 排查慢请求

查看某次请求的 `trace_id`，再在日志里搜索：

```powershell
Select-String -Path logs\2026\05\2026-05-28.jsonl -Pattern "trace_id值"
```

重点看：

- `stage_route`：意图路由耗时。
- `stage_rewrite`：问题改写耗时。
- `stage_pseudo_answer`：伪答案生成耗时。
- `stage_retrieve`：检索耗时。
- `stage_rerank`：二阶段重排耗时。
- `stage_compress`：上下文压缩耗时。
- `stage_answer`：最终 LLM 回答耗时。

如果 `standard` 模式慢，可以用 `--fast` 对比：

```powershell
.\.venv\Scripts\python.exe rags\RAGPipeline.py `
  --fast `
  --question "测试问题"
```

## 7. 日志边界

- 日志不应记录完整 `.env` 或密钥。
- 日志不记录完整文档原文。
- 日志用于定位链路阶段、耗时、数量和异常，不作为最终答案来源。
- 需要完整调试链路时使用 `--show-trace` 或 `--trace-dir`。
